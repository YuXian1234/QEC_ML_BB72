Quantum Repetition Code

This report uses the smallest quantum repetition code \([[3,1,1]]\) to introduce the main objects of the decoding problem: the code space, stabilizers and syndrome, logical operators, the residual logical ambiguity after syndrome measurement, and the quantity computed by the CUDA-QX tensor-network decoder.
The core picture can be summarized in one sentence: three physical qubits encode one logical qubit; the stabilizers test whether the three bits remain locally consistent; the decoder compares the posterior probabilities of two logical classes at fixed syndrome.
code space stabilizer / syndrome logical \(\bar X,\bar Z\) coset probability CUDA-QX tensor network decoder

1. Code Space And Encoded Information

The 3-qubit quantum repetition code encodes one logical qubit into three physical qubits. Its code space is

\[ |0_L\rangle = |000\rangle, \qquad |1_L\rangle = |111\rangle. \]

The logical information is not stored on any single physical qubit. It is stored in the global pattern "all three bits are 0" versus "all three bits are 1." This is the basic reason why the repetition structure can tolerate a single bit-flip.

Why \([[3,1,1]]\)

The code has three physical qubits, so \(n=3\). The code space is two-dimensional, so it encodes one logical qubit, i.e. \(k=1\). As a full quantum stabilizer code, its distance is \(d=1\), because there exists a nontrivial logical \(Z\) operator of weight 1.

However, the numerical example in this report only studies the \(X\)-error sector; in that sector, it is equivalent to a classical \([3,1,3]\) repetition code.

Why It Corrects One Bit-Flip

The discussion here concerns physical \(X\) errors. If only this error type is considered, then a single physical bit-flip breaks local consistency; the stabilizers can detect this change, and the decoder can use the remaining two bits to recover the logical information.

Accordingly, the focus of this report is not the full quantum error model, but the \(X\)-error decoding structure of the quantum repetition code.

2. Stabilizers And Syndrome Map

The two natural stabilizers of the code are

\[ S_1 = Z_1 Z_2, \qquad S_2 = Z_2 Z_3. \]

They test whether qubits 1 and 2 agree, and whether qubits 2 and 3 agree. Writing a physical \(X\) error as the binary vector

\[ e = (e_1,e_2,e_3), \qquad e_i \in \{0,1\}, \]

the syndrome is

\[ s = H e^T \pmod 2, \qquad H= \begin{bmatrix} 1&1&0\\ 0&1&1 \end{bmatrix}. \]

namely

\[ s_1 = e_1 \oplus e_2, \qquad s_2 = e_2 \oplus e_3. \]
Interpretation. The syndrome does not identify a unique physical error. It only reports which adjacent pairs have become inconsistent. The decoder must therefore combine syndrome information with a noise model in order to compare the relative probabilities of different candidate errors.

3. Logical Operators \(\bar X\) And \(\bar Z\)

\(\bar X\): Logical Bit-Flip

\[ \bar X = X_1 X_2 X_3 \]

It satisfies

\[ \bar X |000\rangle = |111\rangle, \qquad \bar X |111\rangle = |000\rangle. \]

Thus it implements the logical bit-flip: it maps logical 0 to logical 1, and maps logical 1 back to logical 0.

\(\bar Z\): Logical Readout Direction

\[ \bar Z \sim Z_1 \sim Z_2 \sim Z_3 \sim Z_1 Z_2 Z_3 \]

Here "\(\sim\)" means that these operators act equivalently on the code space; all of them distinguish \(|0_L\rangle\) from \(|1_L\rangle\).

For the purpose of this report, \(\bar X\) can be viewed as the operator that flips the logical state, while \(\bar Z\) is the direction that distinguishes the logical state.

Why The Decoder Tracks \(\bar Z\)-Flip

The decoding problem here concerns physical \(X\) errors. Physical \(X\) errors affect the sign of logical \(Z\). Therefore the natural question for the decoder is: given a syndrome, has logical \(Z\) flipped or not?

4. Residual Logical Ambiguity After Syndrome Measurement

There are three unknowns, \(e_1,e_2,e_3\), but only two syndrome equations. Therefore, once a syndrome is fixed, the candidate error is typically not unique; instead, two candidates remain.

For example, when the syndrome is \([1,0]\), the equations are

\[ e_1 \oplus e_2 = 1, \qquad e_2 \oplus e_3 = 0. \]

and there are only two solutions:

\[ e = 100 \qquad\text{or}\qquad e = 011. \]

These two errors produce the same syndrome, but they have different logical action. They differ by

\[ 100 \oplus 011 = 111, \]

and \(111\) is precisely the binary representative of logical \(\bar X\). Therefore, at fixed syndrome, the real distinction is:

Does the error belong to the class without logical flip, or to the class with logical flip?

These are exactly the two cosets that the decoder must compare.

A Sector View Of The 8 Error Patterns

From the bit-flip decoding point of view, the eight error patterns can be grouped into two logical sectors:

\[ \mathcal L_0 = \{000,\ 011,\ 101,\ 110\}, \qquad \mathcal L_1 = \{100,\ 010,\ 001,\ 111\}. \]

The two groups are classified by the value of \[ e_1 \oplus e_2 \oplus e_3 \] as follows:

  • \(\mathcal L_0\): an even number of 1s, therefore \(e_1 \oplus e_2 \oplus e_3 = 0\)
  • \(\mathcal L_1\): an odd number of 1s, therefore \(e_1 \oplus e_2 \oplus e_3 = 1\)

This does not mean that the code space contains four logical-0 states. More precisely, in the bit-flip decoding problem, these patterns form two logical sectors: one sector corresponds to no logical flip, and the other corresponds to a logical flip.

In this view, the action of logical \(\bar X = X_1 X_2 X_3\) appears as a one-to-one pairing between the two sectors:

\[ 000 \leftrightarrow 111,\qquad 011 \leftrightarrow 100,\qquad 101 \leftrightarrow 010,\qquad 110 \leftrightarrow 001. \]

Thus \(\bar X\) can be understood as the operator that maps the logical-0 sector to the logical-1 sector, and maps it back. This is also why the two candidates at fixed syndrome typically differ by \(111\).

noise_model = [0.1, 0.1, 0.1]

This means that each of the three physical qubits independently suffers an \(X\) error with probability 0.1, so \[ P(100)=0.1\cdot 0.9\cdot 0.9=0.081, \] \[ P(011)=0.9\cdot 0.1\cdot 0.1=0.009. \]

Meaning Of logical_obs = [1,1,1]

In this script, the three columns of H correspond to the three physical \(X\)-error mechanisms \(X_1,X_2,X_3\). Therefore this row means:

\[ \text{Each of the three physical }X\text{ errors flips the logical } \bar Z \text{ observable being tracked.} \]

Hence the logical flip bit induced by the total error \(e=(e_1,e_2,e_3)\) is

\[ l = e_1 \oplus e_2 \oplus e_3. \]

An odd number of errors gives \(l=1\), while an even number of errors gives \(l=0\).

7. Interpreting The Numerical Output

syndrome = [0,0]

The only compatible errors are 000 and 111. Their probabilities are

\[ P(000)=0.729,\qquad P(111)=0.001. \]

Here 000 belongs to C0, while 111 belongs to C1, so

\[ Z_0=0.729,\qquad Z_1=0.001, \] \[ P(C_1|s)=\frac{0.001}{0.729+0.001}\approx 0.00137. \]

This means that when the syndrome shows no inconsistency, the most likely event is no error rather than a simultaneous flip of all three qubits.

syndrome = [1,0]

The only compatible errors are 100 and 011, with

\[ P(100)=0.081,\qquad P(011)=0.009. \]

These two errors belong to different logical classes:

  • 100 has one error, so \(l=1\), and therefore lies in C1
  • 011 has two errors, so \(l=0\), and therefore lies in C0
\[ P(C_1|s)=\frac{0.081}{0.081+0.009}=0.9. \]

This means that a single-error event is more likely than a double-error event, so the posterior favors the single-error class with logical flip.

syndrome = [0,1] and [1,1]

These two lines have the same numerical values as [1,0] because the toy model is fully symmetric: all three qubits have the same error rate, so the different single-error and double-error combinations are only permutations of each other.

8. CUDA-QX Usage In This Example

In cudaq-qec, the tensor-network decoder can be called in the following minimal form: 

import numpy as np
import cudaq_qec as qec

H = np.array([[1, 1, 0],
              [0, 1, 1]], dtype=np.uint8)
L = np.array([[1, 1, 1]], dtype=np.uint8)
p = [0.1, 0.1, 0.1]
syndromes = np.array([[0, 0],
                      [1, 0],
                      [0, 1],
                      [1, 1]], dtype=np.uint8)

decoder = qec.get_decoder(
    "tensor_network_decoder",
    H,
    logical_obs=L,
    noise_model=p,
    dtype="float64",
    device="cuda",
)

result = decoder.decode_batch(syndromes)
posterior = result.result
1. Provide H Define the syndrome constraints, i.e. the connectivity between error variables and parity checks.
2. Provide logical_obs Specify which logical observable flip should be tracked.
3. Provide noise_model Assign a prior probability to each error mechanism.
4. Call decode() / decode_batch() Return the logical-flip posterior at the given syndrome.

CPU And GPU Backends

The example script supports both --device cpu and --device cuda. On GPU, CUDA-QX preferentially uses cuTensorNet / cuQuantum; on CPU, it falls back to torch / opt_einsum.

This does not change the mathematical object being computed; it only changes the contraction backend and the resulting performance.

What optimize_path() Measures

The reported quantities Naive scaling, Optimized scaling, and Largest intermediate are all properties of the contraction path. They are tiny for this 3-bit toy problem, but for BB72-scale instances they directly determine whether the TN decoder is practical.

9. Key Takeaways

The code space of this repetition code is \(|000\rangle\) and \(|111\rangle\); the stabilizers only test whether neighboring qubits remain consistent, so one bit of logical ambiguity typically remains after syndrome measurement. The CUDA-QX tensor-network decoder then groups all syndrome-compatible physical errors by logical class and compares the total probability mass of the resulting groups.

The Python example displays this entire pipeline explicitly: H defines the syndrome map, logical_obs defines the logical classes, noise_model provides the prior, and decode_batch() returns the posterior. Although the example is small, it already contains the core idea needed later for BB72, qLDPC decoding, and circuit-level DEM decoding.
