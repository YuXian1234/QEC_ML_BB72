BB72 BP+OSD Baselines and TN Reconstruction Results

BB72 BP+OSD baselines, CUDA-QX tensor-network logical queries, and one full 4096-sector logical-posterior reconstruction for a sampled BB72 syndrome.
Bottom line. Two BB72 BP+OSD baselines are established. On the tensor-network side, we have now gone beyond a single logical-parity query: for one sampled BB72 syndrome, the full \(4096\)-sector posterior has been reconstructed from CUDA-QX parity queries. The main remaining issue is scalability, because almost all runtime is spent in contraction-path optimization rather than in the final Walsh-Hadamard reconstruction.

1. Current objective

The near-term goal is not to claim that tensor networks already replace BP+OSD on BB72. The correct sequence is more disciplined:

\[ \text{fast BP+OSD baselines} \;\longrightarrow\; \text{single BB72 TN logical query} \;\longrightarrow\; \text{full 4096-sector posterior reconstruction} \;\longrightarrow\; \text{reduce query count for MLD / search}. \]

This matters because BP+OSD and the TN decoder are not computing the same object. BP+OSD is a fast decoder baseline that returns a candidate correction. The TN route is aimed at logical-sector probability information.

5. What one TN query computes

One TN query starts from a 12-bit logical mask

\[ a\in\mathbb F_2^{12}, \]

which specifies a binary logical question

\[ a\cdot\lambda = \sum_{j=1}^{12} a_j\lambda_j \pmod 2. \]

The decoder does not receive \(a\) alone. It first converts that logical question into a physical logical observable

\[ \texttt{logical\_obs}=aL_X, \qquad a\in\mathbb F_2^{12},\; L_X\in\mathbb F_2^{12\times72}. \]

where \(L_X\) is the chosen \(12\times72\) logical-\(X\) basis matrix. This is why the report contains both a 12-bit logical mask and a much shorter physical logical observable support: they live in different spaces. The mask \(a\) lives in logical space, while \(aL_X\) is a 72-qubit physical operator whose support can become much smaller after mod-2 cancellation.

For one chosen mask \(a\), the TN decoder computes a binary split of all \(4096\) logical sectors:

\[ Z_a^{(0)}(s)=\sum_{\lambda:\,a\cdot\lambda=0} Z_\lambda(s), \qquad Z_a^{(1)}(s)=\sum_{\lambda:\,a\cdot\lambda=1} Z_\lambda(s). \]

It then returns the logical flip probability

\[ P(a\cdot\lambda=1\mid s) = \frac{Z_a^{(1)}(s)}{Z_a^{(0)}(s)+Z_a^{(1)}(s)}. \]

6. Full 4096-sector posterior reconstruction has now been demonstrated

The reconstruction script evaluates all nonzero parity masks \(a\in\mathbb F_2^{12}\), collects

\[ p_a(s)=P(a\cdot\lambda=1\mid s), \qquad m_a(s)=1-2p_a(s), \]

and then applies the inverse Walsh-Hadamard transform

\[ P(\lambda\mid s) = 2^{-12} \sum_{a\in\mathbb F_2^{12}} m_a(s)\, (-1)^{a\cdot\lambda}. \]

So the current result is no longer only a single flip probability. For one sampled syndrome, the full posterior over all

\[ 2^{12}=4096 \]

logical sectors has already been reconstructed.

7. What the result means for next steps

The main challenge has now shifted. The issue is no longer whether the parity-query route can be turned into a full logical posterior; that has already been demonstrated on this sampled example. The issue is how to reduce the number of expensive logical queries while preserving the useful posterior information.

The runtime breakdown is especially clear:

  • \(4095\) nontrivial TN queries were required for this direct reconstruction.
  • Total runtime was \(22578.85\) s, or about \(6.27\) hours.
  • Path optimization alone consumed \(22382.31\) s, about \(99.13\%\) of the total.
  • The inverse Walsh-Hadamard step took only \(0.008\) s and is negligible.
So the right message at this stage is not “TN is already a practical BB72 production decoder.” The right message is: the full BB72 logical posterior can be reconstructed from CUDA-QX TN queries, and the next algorithmic task is to reduce how many of those expensive queries must be asked.

Natural next directions include:

  • structured tree search or branch-and-bound over logical sectors or parity constraints;
  • query-ordering rules that ask cheaper or more informative logical questions first;
  • learned guidance that predicts which sector branches or parity queries are worth evaluating;
  • contraction-path reuse, batching, or other engineering strategies that reduce repeated pathfinding cost.
\[ \boxed{ \text{BP+OSD baselines are established; full BB72 posterior reconstruction has been demonstrated once; the next step is to reduce TN query cost.} } \]
